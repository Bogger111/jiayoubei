# 家有备助手与工具实测

2026-10-31。当前主入口为 <http://localhost:3000/>，`/ai` 为兼容入口。大对话框是助手页主视觉，顶部始终保留“助手、家庭、空间、行动、设备、记忆”。原有工作台继续保留。

## 在对话中使用

- “记住爸爸习惯晚上八点在客厅阅读。”保存家庭记忆；后续可询问阅读约定，检索实际记录。
- “把客厅主灯调到 60%，厨房窗帘调到 50%。”先读取已部署设备，再显示完整计划；点击确认后执行，回执也在对话内查看。
- 点击输入框加号，添加房间照片，再说“根据这些照片搭建我的家，先给我预览”。草稿异步生成并在原对话更新；可打开原生编辑器微调家具，再保存为家庭空间。
- “把沙发转 30 度。”模型先读取当前布局与家具编号，再修改支持的家具位置、角度、尺寸或颜色；布局保留版本。
- “安排家人整理药箱。”模型可读取家庭成员并创建真实待认领任务；信息不够时需要补充。

对话与回执保存在服务端。刷新恢复当前对话，“最近对话”可以重新打开旧对话。“新对话”保留家庭记忆、空间和设备记录。

## 实际调用链

`AssistantHome → /api/assistant → assistant-service → 本机私有模型服务 → 模型函数调用 → 已注册家庭工具 → 真实结果 → 模型下一轮`

主助手没有前端关键词分流或伪执行回退。每轮把可用工具、最近对话和已有回执交给模型，由模型选择工具和参数。服务端验证工具名称、参数、当前身份、家庭归属与布局版本，再调用原有服务。模型读取工具结果后继续安排或回答，界面显示实际工具步骤及可操作结果卡。

| 工具 | 实际服务 |
| --- | --- |
| `family_context` | 当前家庭、成员、身份与时间 |
| `memory_save` / `memory_search` | 家庭记忆保存、中文向量与关键词检索、来源 |
| `devices_list` | 已部署设备、状态、来源、权限与允许能力 |
| `devices_plan` / `devices_plan_status` | 待批准多设备计划、执行状态与逐项回执 |
| `space_read` / `space_update` | 当前布局、家具目录与版本校验后的微调 |
| `space_build` / `space_status` | 已上传照片的真实生成任务、进度与草稿 |
| `space_apply` | 用户要求保存时应用草稿，保留上一版家庭布局 |
| `family_task` | 原有家庭任务创建服务 |

模型没有设备批准工具。执行沿用统一设备服务的权限、计划版本、单次领取及设备租约。示例设备与网关设备来源分别记录，不把软件状态称为实物效果。

模型调用与照片识别使用本机已有 DeepSeek 私有配置；产品页不显示供应商、凭据或配置入口。助手主模型通过函数调用规划；照片搭建工具另行把用户授权上传的照片送到视觉接口，返回受约束的结构化布局，并由原生家具引擎渲染。没有执行模型生成的任意程序。

## 数据与接口

新增 D1 表为 `assistant_conversations` 和 `assistant_runs`。对话按 `family_id + user_id` 隔离；家庭成员也不能凭编号读取另一成员对话。照片另行验证当前家庭归属。

- `GET /api/assistant`：当前用户最近 30 段对话。
- `GET /api/assistant?conversationId=...`：该对话最近 50 次请求，按时间排列。
- `GET /api/assistant?id=...`：一次请求的实际进度、步骤、回复和结果卡。
- `POST /api/assistant`：`id`、`conversationId`、`query`、`photoIds`。同编号同内容直接返回已有记录，避免重复调用或写入；同编号不同内容拒绝。

每次最多 8 轮模型调用、14 次工具调用，同一对话仅允许一个进行中的请求。模型上下文保留最近 7 次对话；读取旧对话不会重复执行工具。前端发送时同步轮询已保存进度。连接失败时保留已取得回执并说明未完成部分，不伪造成功；超过 6 分钟未更新的请求在读取单次进度时标为中断。

## 真实模型运行

以下使用当前配置的真实付费模型，以及临时隔离的 D1/R2 家庭。没有写入当前演示家庭。

**记忆与设备：** `test-results/home-upgrade/assistant-live-result.json`。模型自行选择 `memory_save → devices_list → devices_plan`，约 4.5 秒完成安排。记忆实际保存；完整计划保留主灯 60% 亮度与窗帘 50% 目标；批准前设备没有变化，明确批准后样例适配器保存状态与逐项回执。重复提交返回同一记录，未重复计费调用。

**照片建模：** `assistant-live-photo-result.json`。8 张公开 VGGT room 照片实际生成 1 个房间、15 件家具，生成服务用时 8.35 秒。浏览器在同一对话打开原生编辑器、新增办公椅并保存为 16 件家具，然后应用为家庭空间。整段流程约 16.2 秒，无浏览器脚本错误。输入是公开照片，来源和许可见根目录 `appendix.md`。

第一次照片调用因模型输出截断失败。调整非思考模式、紧凑家具 JSON 及输出限额后，第二次成功；没有自动重试计费请求。单次成功证明真实流程运行，未测量几何或家具识别准确率。

`assistant-live-photo-preview.png` 与 `assistant-live-photo-saved.png` 是实测当时截图；后续 `assistant-live-photo-framed.png`、`assistant-live-photo-framed-mobile.png` 用同一次实际输出复查最新取景和容器高度，没有再次请求模型。原样例四房、66 家具继续保留。

## 复现

先构建，再运行隔离检查；这些检查用明确的模型固定响应，不产生云端费用：

```powershell
npm run build
npm run typecheck
npm run test:unit
npm run test:assistant:api
npm run test:assistant:home
npm run test:space:api
npm run test:home-control:e2e
```

浏览器检查需要本机 `localhost:3000` 已运行；接口检查自动建立临时认证、D1/R2 与固定响应服务。Python 请求契约可分别运行 `services/home-engine/test_assistant_provider.py` 与 `test_scene_provider.py`。

以下是可选的真实模型检查，**显式加 `--live` 才会调用付费服务**。要求私有引擎与已配置凭据可用，照片浏览器检查还需开发页面运行：

```powershell
node scripts/home/verify-assistant-live.mjs --live
node scripts/home/verify-assistant-photos-live.mjs --live
```

记录与截图写入被 Git 忽略的 `test-results/home-upgrade/`。脚本私下读取本机引擎连接资料，不打印凭据；不加参数直接退出，不启动请求。实物 Home Assistant / ESP32 尚未连接，当前设备证据限软件样例与此前网关接口契约。
