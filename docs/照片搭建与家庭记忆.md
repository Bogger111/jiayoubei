# 照片搭建与家庭记忆

本轮产品目标是：输入几张家的照片，由 AI 选家具、整理布局和颜色，用家有备的三维家具库生成接近样例的家庭模型，随后可以编辑、保存和恢复。语音功能与 PPT 未在本轮修改。

## 现在从哪里打开

本机助手：<http://localhost:3000/>。在输入框加号中添加房间照片，再告诉助手如何搭建，预览、编辑和保存均可在对话中完成。独立入口 <http://localhost:3000/create-space> 与现有空间页继续保留。

已完成本机安装时，双击项目根目录 `启动家有备.cmd`，或运行：

```powershell
pwsh -File scripts/home/start.ps1 -Open
```

生成服务由本机后台配置，产品页不展示密钥入口或服务商名称。上传 4—10 张不同角度的房间照片。点击“生成三维家居”后，先预览，再进入“微调家具”；确认后保存为家庭空间。房间尺寸、位置、角度、家具尺寸、颜色和材质可在原生编辑器中调整。也可以使用手机拍照或电脑摄像头逐张拍摄。

DeepSeek 使用兼容 OpenAI 的接口格式，密钥来自 DeepSeek 平台，不使用 OpenAI 账户密钥。当前模型配置为 `deepseek-flash`，接口为 `https://api.deepseek.com/chat/completions`，支持多图输入与 JSON Output。模型需要账户可用额度。

独立页面点击“生成三维家居”，或在助手中附上照片并提出搭建要求，才会提交生成请求。配置密钥不生成场景。所选照片会发往 DeepSeek；输入框保留云端处理说明。连续的视频感知功能仍沿用本机处理路径。

## 生成的是什么

AI 返回房间与家具的结构化布局，不在浏览器执行它生成的任意程序。服务端匹配同款三维家具库，限制尺寸、坐标、颜色和材质，再交给三维引擎渲染。因此画风与现有样例一致，家具可以分别编辑。

这是近似的家居布局表达。它适合“看起来接近照片、整体整洁、能够调整”的产品目标；尺寸和未拍到的部分允许推断，用户可以修改。生成草稿先独立保存，点击确认才替换家庭空间。替换前的布局会保留，可在空间页的“布局历史”恢复。

模型可能漏掉物件、误判房间连接或摆放方向。已使用 8 张公开房间照片完成真实云端调用，得到 1 个房间、15 件家具的可编辑草稿；又在对话内新增椅子，保存为 16 件家具。该次结果验证生成与编辑流程，没有标注精度测量，也不是本团队自采家庭照片。固定响应测试另行记录，不计入真实推理结果。

## 已验证的范围

- 本机 RTX 5070 Laptop GPU、PyTorch 2.8.0+cu128 上运行了真实几何与中文语义模型。
- 使用 8 张公开房间照片实际完成 DA3-BASE 深度与相机恢复，形成可查看的表面扫描；分离家具可以改名、移动、保存并重新读取，也可以导出 GLB。
- 原生三维家具编辑器经过新增家具、保存、刷新恢复的浏览器验证。
- 中文 BGE 向量与关键词混合检索实际运行；新补充的家庭记忆可检索并显示来源。未安装本地模型时保留关键词与原文摘录。
- 新 DeepSeek 路线经过固定响应的请求契约、权限、重复提交、布局规范化、预览、编辑、应用和恢复测试；另有真实模型读取公开照片并完成对话内建模、编辑及应用的记录 `assistant-live-photo-result.json`。
- 摄像头界面使用浏览器模拟摄像头验证拍照与关闭；没有将模拟摄像头结果当作真实家庭重建输入。

## 文件与数据

- 三维与生成页面：`app/components/HomeSpace.tsx`、`PhotoHomeBuilder.tsx`、`ScenePhotoPicker.tsx`、`DioramaView.tsx`。
- 家庭记忆：`app/components/FamilyMemory.tsx`、`lib/home-memory.ts`、`lib/server/home-memory-service.ts`。
- 场景约束与家具目录：`lib/space/scene-plan.ts`、`furniture-catalog.json`。
- 服务端接口：`app/api/scene-plans/route.ts`、`lib/server/scene-service.ts`。
- 本机模型与接口服务：`services/home-engine/engine.py`、`scene_provider.py`。
- 家庭布局、版本、草稿与记忆：本地 D1。照片与 GLB：按家庭隔离的本地 R2。
- DeepSeek 密钥：`.care-local/home-upgrade/scene-provider.json`，按家庭保存；文件被 Git 忽略，API 不返回密钥。产品页面没有密钥输入或更换入口。
- 本机服务连接令牌：`.care-local/home-upgrade/engine-config.json` 与 `.dev.vars`，均不提交 Git。
- 本地模型、运行环境、任务记录：`.care-local/home-upgrade/`。模型版本与 SHA-256 见 `services/home-engine/models.lock.json`。

这轮没有创建远端 R2 桶、上线服务或推送 GitHub。部署版本需要单独配置媒体桶与可访问的后端服务；私有配置接口仅允许本机管理员调用。

## 新电脑安装

需要 Node.js 22.13+、Python 与 uv。只使用 DeepSeek 照片搭建时可以轻量安装，无需下载 GPU 模型：

```powershell
npm ci
python services/home-engine/bootstrap.py --api-only
pwsh -File scripts/home/start.ps1 -Open
```

需要本机几何扫描与语义记忆模型时，使用完整安装：

```powershell
python services/home-engine/bootstrap.py
python services/home-engine/bootstrap.py --verify
```

完整安装使用隔离 Python 3.12 环境，固定 torch/torchvision CUDA 12.8 组合与模型版本。不会安装到系统 Python 环境。模型文件只从固定版本下载并校验摘要。停止本项目启动的服务：

```powershell
pwsh -File scripts/home/stop.ps1
```

手机拍好的照片可以传到电脑上传；通过手机浏览器直接调用摄像头需要可达的 HTTPS 地址。电脑的 localhost 页面可以直接请求摄像头，且不请求麦克风。

## 设备与 Agent 框架更新

当前产品重点为：以 `/` 助手为主入口，用户布置三维空间并部署设备，将统一的设备能力交给 Agent 整理完整计划，确认后统一调控。`/devices` 保留设备部署与设置；三维样例继续保留。家庭动态和习惯不会自动填充样例。设备操作回执独立保存，不会为了展示自动写入记忆时间线。

开发契约、真实设备网关接入与验收方式见 [统一设备与 Agent 框架](统一设备与Agent框架.md)。
