# 视觉监测评测方案

更新：2026-10-28。已完成 32 段 URFD 公开实验视频的小规模探索；本方案要求的独立受试者评测、逐帧起点标注和长时误报统计仍未完成。完整结果见 `public/evidence/index.html` 与 `public/evidence/vision-*.json`。

第一批 fall/adl 01–08 用于开发分析；规则冻结后运行第二批 09–16。每批 8 段摔倒、8 段日常动作，所有片段保留。新版 Lite 两批分别检出 2/8、3/8，Full 分别 3/8、2/8；日常动作均 0/8 误触发。这里没有受试者隔离，不能称为独立泛化验证。旧 V1 使用相同模型输出，四次均 0/8 检出；刻意简化的单帧倾角参考保存在结果中。

## 当前系统

应用已有本机姿态推理、固定画面站立校准、时序疑似摔倒判断，以及事件到人工核实任务的关联。后台线程优先，兼容方式回退。摄像头与视频回放的来源分别记录。

当前告警使用图像中的姿态变化。相对 3D 躯干角度用于观察，尚未参与告警决定。MediaPipe 同时提供图像关键点与 3D 关键点；3D 坐标以髋部中点为原点。由此推断，这组输出适合比较身体内部姿态，不能直接代表人在房间中的绝对位置或距地高度。[官方输出说明](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js)

现有 V2 约 0.8 秒站立或坐直校准、0.6 秒低位保持、以躯干长度归一化下降等参数仍是原型规则，尚未通过独立受试者评测选定。V1 冻结于 `benchmarks/baselines/fall-detector-v1.ts`。现有单元与假摄像头检查验证逻辑和资源管理，不替代下述评测。世界关键点目前仅用于旋转观察与诊断，不参与告警判定。

## 先建立可追溯的数据清单

每段素材保存以下信息，尚未取得的数据留空：

| 字段 | 记录内容 |
| --- | --- |
| clip_id / group_id | 素材唯一编号；同一人、录制场次及切片的共同分组 |
| source / permission | 原始来源与使用许可；不要只保留下载链接 |
| subject / session / camera | 匿名人物编号、录制场次、镜头编号 |
| duration / resolution / fps | 实际时长、画面尺寸与帧率 |
| activity | 摔倒，或坐下、躺下、弯腰、捡物、走出画面等日常动作 |
| onset / end | 人工标注的事件开始、结束视频时间，单位秒 |
| visibility / people / angle | 遮挡、人数、镜头方向、身体是否完整入画 |
| calibration | 开始时是否有清晰站立段，时长是否足够 |
| annotator / revision | 标注人、复核人、分歧与修订记录 |
| split / checksum | 开发或验证或保留测试集；素材文件摘要 |

使用已获许可的既有视频和日常活动素材。若素材有多次事件，逐个标注。人物编号不使用真实姓名。

同一个人的同一次录制及其切片进入同一个分组，不能把相邻帧随机分配到验证和测试。优先按人物与场次分组，另记录跨镜头结果。片段过短、站立基准缺失、多人或遮挡都单独标记。

## 冻结验证顺序

1. 固定一份当前 2D 规则的基线版本，记录代码版本、参数、模型文件摘要和运行设备。
2. 在开发素材上检查标注、日志格式和运行方式。在验证素材上选参数。
3. 在查看保留测试集结果前，冻结参数、素材清单、匹配窗口、统计方法和比较对象。
4. 用同一份保留测试集分别运行基线与候选方案。不得按测试结果反复调整参数再宣称独立验证。
5. 修复后重新评测时记录修改原因，并另留未参与调参的测试素材。

视频以正常速度运行，记录实际送入模型的帧时间。暂停、跳转、加速与窗口切换作为独立资源和轨迹测试，不混入正常识别准确率。

## 统计事件与真实负样本时长

- **事件召回率**：匹配到的真实摔倒事件数 / 人工标注的真实摔倒事件数。
- **事件精确率**：匹配到的真实摔倒事件数 / 系统产生的告警数。
- **日常活动误报频率**：日常活动片段中的错误告警数 / 实际有效观察小时数。
- **重复告警**：同一真实事件匹配一条告警，其余另计，不能把多个告警当成多个正确事件。
- **检测延迟**：告警视频时间减人工标注的事件开始时间；记录中位数与较慢样本，不只展示平均值。
- **运行成本**：冷启动时间、单帧推理耗时及较慢帧、实际处理帧率、停止后资源释放、页面交互是否受阻。
- **可用覆盖率**：所有素材中能够完成校准和持续观察的比例；同时给出各失败原因。

事件匹配时间窗口必须预先选定并说明。逐帧正确率不能替代事件召回率，长时间没有事故也不能证明事故识别可靠。分母为零时填写“无法计算”，不要填写 0% 或 100%。

分别报告“满足原型输入条件”的子集和包含全部素材的结果。缺少校准或不支持的场景中的真实摔倒应在全量结果中体现漏报，不能删除后提高数字。未出现告警但无法观察人体的片段，也不能算成正常动作识别成功。

所有结果保留事件清单与错误案例。按人物或录制场次进行分组统计；样本很少时报告具体条数与不确定性，避免只展示一个百分比。

## 3D 成分的潜在增益

| 比较方案 | 当前状态 | 要检验的问题 |
| --- | --- | --- |
| A：现有 2D 时序规则 | 已实现原型 | 建立误报、漏报和性能基线 |
| B：A 加相对 3D 躯干变化 | 待独立实现与验证 | 侧身、弯腰和镜头方向变化时，是否减少误报并保持召回 |
| C：轻量关键点时序分类 | 后续候选 | 是否需要学习更长动作序列；是否有足够独立标注数据 |
| D：额外完整人体 3D 重建模型 | 尚未引入 | B/C 仍无法解决的问题是否值得额外计算和维护成本 |

先比较 A 与 B，复用当前关键点输出即可开展实验。B 不直接替换告警规则，先离线运行并保留 A 的结果。候选方案采用同一素材、同一事件匹配方式和同一设备比较。

将接受标准在实验前填入记录：允许的日常误报频率、最低事件召回、可接受检测延迟、目标手机运行成本。标准来自使用场景与证据，当前没有填入虚构数值，也没有达到标准的结论。

只有当候选方案在保留测试集显示稳定收益，失败案例可解释，且目标设备成本可接受时，才考虑加入正式检测链。单段视频显示更漂亮的骨架，不足以支持额外模型升级。

## 与答辩展示衔接

当前可以展示：本机关键点、站立基准、相对 3D 姿态、疑似事件、关联核实任务、停止释放资源，以及明确的视频回放标识。

取得真实数据后，补充：数据许可、素材分组、冻结参数、独立测试、完整错误案例和设备运行记录。外部通知送达、真实设备执行与线上部署分别验证，不并入视觉识别指标。
