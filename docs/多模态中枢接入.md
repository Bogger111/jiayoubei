# 多模态家庭中枢接入

## 本地查看

运行 `npm run dev -- --port 3000`，打开 `/home-agent`。首页日期旁和“更多功能”也有入口。默认演示家庭可点“载入软件演练”；时间线、设备安排与处理记录保存在本地 D1。

实际账号模式沿用 `docs/care-p0/启动与复现.md`，不要覆盖既有 `.dev.vars` 或清空 `.wrangler/`。

## 完整体验入口

`/experience` 复用同一后端，加入四类可操作演示。载入演练只增加或更新带有 synthetic/replay 标签的事件，不清空当前家庭数据。三种情景合计九个固定事件标识，重复载入保持去重。对话模式显示预置语句，实际调用工具接口，准备操作仍需批准。失败保留错误与重试入口。

`npm run experience:prove` 录制隔离后端的实际操作，输出四张截图、一段分章节录像与 `experience-browser.json`。录屏与截图在比赛文件构建时内嵌。四张界面效果示例、两种提示音的来源与许可见 `appendix.md`。

## 时间线同步

服务端私有 `.dev.vars` / Worker secrets 中设置：

```text
HOME_ASSISTANT_URL=<自己的实例>
HOME_ASSISTANT_TOKEN=<本地保管>
HOME_ASSISTANT_FAMILY_ID=<当前登录家庭ID>
HOME_TIMELINE_CAMERAS=camera.living_room,camera.front_door
CARE_CAPTURE_CATEGORY=bench
DEVICE_DRIVER=home_assistant
```

实例需已有时间线事件接口。字段与固定版本见 `third_party/ha-llmvision/timeline_openapi_specs.yaml`。只有列出的公共区域实体会导入；上游图像 URL 不返回浏览器，图像身份不当作具体家人确认。采集分类按实际台架、知情角色演练或自然使用选择。凭据不放前端或版本库。

未配置时按钮会显示连接待准备；软件演练仍可使用。接口配置不代表物理效果已验证。

## 家庭工具

登录后向 `/api/multimodal/mcp` 发送：

```json
{"type":"mcp","session_id":"my-terminal","payload":{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}}
```

同样可发送普通 JSON-RPC。`initialize` 返回协议版本和工具能力；`tools/call` 以 `params.name` 指定家庭工具。HTTP 使用当前用户会话，前端不持有设备令牌。

工具是 `home.timeline`、`home.light.prepare` 与 `home.care.prepare`。准备操作不会直接执行；灯光需管理员在页面确认，联系计划在 `/care?caseId=...` 核对批准。不存在通用 shell、任意设备操作或绕过家人确认的工具。

该入口只验证工具协议，尚未提供完整语音终端的音频、传输和身份注册服务。不要把标准消息封装可用当作 ESP32 已联调成功。

## 检查与录屏

```text
npm run build
npm run test:home:unit
npm run test:home:api
npm run home:prove
```

API 与录屏脚本使用隔离 D1，不操作既有家庭数据库或真实设备。新录像默认使用 localhost:3000 的前端，业务接口被连接至临时演练后端，录制文件写入 `public/evidence/`。器材联调另见原硬件操作包。

来源、改动和随附许可统一见根目录 `appendix.md`。
