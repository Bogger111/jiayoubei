# 家有备现场演示

## 开始前

双击项目根目录的 `启动视觉检测.cmd`，保持服务窗口打开。主页为 `http://localhost:3000/`，场景入口为 `/demo`，视觉页面为 `/cv`。

如果页面打不开，先查看启动窗口的错误；确认没有其他程序占用 3000 端口。可使用项目 README 的启动步骤。首次使用需要安装依赖。

默认前端为示例家庭演示。示例模式下整页刷新会恢复初始家庭记录；设置页的阅读偏好仍保存在浏览器中。服务端数据模式的记录存入 D1。展示时分别说明数据来源、输入来源和 AI 分析方式。

## 推荐顺序（约 7 分钟）

| 时间 | 页面与操作 | 可以说明的能力 |
| --- | --- | --- |
| 0:00–1:00 | 家庭总览，指出当前事项与关联事件 | 优先展示需要处理的事项，统计来自当前记录 |
| 1:00–2:30 | 家庭任务 → 新建任务 → 选择负责人、期限、来源 | 成员分工、关联事件与操作记录 |
| 2:30–3:30 | 填写处理记录 → 保存 → 确认完成 → 查看事件 | 保存证据与完成确认分开，关联事件回传结果 |
| 3:30–4:30 | Demo 控制台 → 陌生访客 → 查看授权 → 拒绝 → 审计 | 高风险动作需要决定，授权只保存决定，未自动操作门锁 |
| 4:30–6:00 | 视觉监测 → 选择已获许可的本地视频 | 本机姿态推理、站立基准、相对 3D 姿态、时序判断 |
| 6:00–7:00 | 设置 → 更大文字 / 减少动画 / 导出 | 手机与长辈阅读、家庭记录可留存 |

### 视觉演示的条件

固定镜头，让一人的肩、髋和脚踝进入画面。先保持站立约 0.8 秒，建立基准。规则观察短时间下降与横向倾斜，并要求低位保持约 1.2 秒。

使用已获许可的视频回放展示完整过程。无需在现场模仿危险动作。多人入镜、遮挡、暂停、跳转或长时间丢帧会中断轨迹并重新校准。停止检测会释放摄像头和检测资源。

触发后进入疑似事件与核实任务，填写回放观察结果。回放记录明确标为验证，不能讲成实时事故。没有合适的视频时，可以展示摄像头输入、校准状态与资源释放，不宣称已验证真实摔倒识别效果。

### AI 助手

输入“帮我核实家人的近况，并记录确认结果”。示例模式会创建新的演示事件与任务；每次任务都有自己的记录。新对话不会删除已创建的家庭任务。

真实数据模式按配置调用模型或使用规则分析。普通问候不生成应急事件，模型引用的成员需匹配家庭资料。专业救援和外部联系仍由人决定。

### 可选：真实账号协作（另加约 2 分钟）

使用启用真实认证的独立测试环境，管理员在“家庭成员”添加资料，进入详情生成指定邮箱的邀请。用另一浏览器会话打开链接，以自己的密码加入；展示普通成员可查看家庭记录，以及管理员管理入口不可操作。管理员更新记录后能看到已关联账号。

再让普通成员接受自己的任务，点击请求家庭帮助。管理员从自己的通知中心打开关联任务并接手，更新记录后两个会话都能看到负责人变化。通知的已读状态各自保存，求助处理后保留记录。

链接需要手动转交，有效 24 小时且只能使用一次。可展示撤销未使用邀请，或确认停止普通成员账号访问。成员资料与已有任务会保留，旧会话下次更新记录后返回登录。默认示例模式不创建真实账号。

## 展示时的措辞

| 范围 | 合适的说明 |
| --- | --- |
| 已实现 | 页面协作、直接创建任务、处理记录、完成确认、授权决定、审计、阅读偏好 |
| 已运行的本地验证 | 家庭数据隔离、保存失败重试、并发提交、登录权限、后台姿态线程与兼容回退 |
| 原型 | 本机疑似摔倒时序识别；相对 3D 姿态用于辅助观察 |
| 待实际验证 | 真实摔倒灵敏度与误报率、真实设备执行、外部通知送达、线上部署 |

不要把假摄像头、合成姿态或本地模拟结果换算成识别准确率。历史访谈人数、模型成功率和设备成功率需要原始记录才能使用。

## 后续提升的证据

下一阶段先建立有人工标签的摔倒与日常活动视频集，并固定参数、评测协议和保留测试集。记录误报、漏报、遮挡、多人、镜头角度、不同设备性能。根据这些结果决定是否需要额外的 Human3D Motion 模型。

当前没有必要为展示效果加入重量较大的 3D 模型；已有相对 3D 关键点可观察姿态，不能测量人在房间中的绝对高度。
