# 真人采集操作包

以下规模均为拟开展目标。目前没有真实家庭样本，不能将本文件中的人数、次数或时间写成已获得成果。

## 台架：8 类情景，各约 3 次

正常活动；约定午休；持续未回应；门磁变化但是否离家未知；设备断线；明确回应后停止；重复及乱序事件；回应与超时同时发生。

每次填写 `examples/care/bench-records.csv`：批次、唯一序列 ID、类别、开始/结束时间、原始事件文件、设备与固件、软件版本、观察到的 LED 变化时间、观察者、失败/未知、备注。重复播放同一序列仍是同一真实样本；live/replay 与 bench 等类别分别记录。

台架结论限定为指定设备和条件下的链路行为、故障与延迟，不计算家庭识别准确率。

## 访谈提纲

分别问子女、父母与联系人，不只问购买者。

1. 最近一次暂时联系不上时，具体发生什么、谁先行动、谁接手、最后怎么确认？
2. 哪些解释、追问或重复联系最费精力？已有电话/家庭群和联系人表是否已经够用？
3. 父母希望何时不被打扰？愿意分享哪些设备线索，哪些不同意？
4. 联系人愿意响应哪些任务，在什么时段、怎样拒绝或转交？
5. 安装和维护由谁完成？掉线时谁处理？
6. 没有异常发生时，这个服务还有什么价值？谁愿意付费，实际购买条件是什么？

保存原始授权记录与去标识访谈摘要；拒绝、退出和“电话就够用”同样保留。

## 协作演练：约 3 个家庭组合

使用知情角色任务，不让家人真实失联，不制造疾病或跌倒。每个组合分别使用“电话/家庭群＋约定联系人表”和家有备；任务信息与联系人条件相当，交替安排先后顺序。

记录主动协调时间、总经过时间、首位明确接手时间、联系/追问次数、交接不清次数、父母负担、联系人负担，以及是否正确停止后续安排。主动协调时间使用人工操作分段计时，不能直接用总经过时间代替。

采用 `examples/care/collection-template.jsonl` 的字段，正式数据单独保存。每条记录给定 householdId、pairedTaskId、method、来源类别、原始记录引用与同意记录编号。不同方法的比较先按同一家庭和同一角色任务配对；小样本只描述观察，不外推因果效果。

## 5 户 / 14 天可行性试用

第 0 天：分别取得子女、父母、联系人的同意，约定可用时段、授权范围与退出方式；完成设备与联系人设置。

第 1–3 天：每日检查安装问题、掉线、误打扰和支持时间。第 7 天：分别访谈三个角色。第 14 天：记录是否愿意继续、实际付费条件与退出原因。

家庭可以暂停、撤回授权或退出；退出后停止采集。保留已采集数据的处理方式按事先同意执行。正式联系资料与匿名分析 ID 分开，仓库只接收去标识记录，不提交电话、地址、凭据或摄像头画面。

5 户完整参与 14 天最多是 70 家庭日，独立家庭仍为 5 户。若没有自然发生、独立标注的需要核实事件，召回率显示“不可估计”。区分规则违反导致的错误触发和家庭主观觉得无必要的打扰。

导入有效暴露时使用 eventKind=usage_interval，并给出 exposureStartAt / exposureEndAt（实际有效观测起止时间）。报告按家庭合并重叠区间，再除以 24 小时计算有效家庭日；一次心跳或一次点击不能算一天。

## P2 个体化接口

先积累有效活动、设备在线、缺失区间和家庭时段约定。个人基线以家庭和时段分组，可从经验分位数开始；按时间留出验证，与固定阈值 B0、证据＋约定 B1 比较。样本不足时保持 B1，不输出危险概率，不声称系统已经学会生活规律。
