# 启动与复现

环境：Node 22.13 及以上；本次使用 Node 24.18、Windows Chrome。浏览器脚本默认 Chrome 安装路径为 `C:/Program Files/Google/Chrome/Application/chrome.exe`。

## 查看当前版本

在项目根目录执行 `npm run dev -- --port 3000`。

- `/`：保持现有风格的家庭首页，软件演练支持明确接手和结构化结果。
- `/care`：访问真实后端的关怀工作台，计划和截止时间保存到 D1；软件导入会明确标 synthetic。
- `/competition/`：当前离线比赛演示。
- `/care-evidence/`：关怀确认的软件证据与真实采集状态报告。

默认前端仍是演示家庭，不能用它冒充两个真实成员账号。正式联调时按下节配置。

## 配置真实成员协作

1. 在本地被忽略的 `.dev.vars` 设置 `AUTH_MODE=real`，配置独立的随机 AUTH_SECRET。不要提交密钥；部署使用 Worker secrets。
2. 在本地 `.env` 设置 `VITE_USE_MOCK=false`，保持 VITE_API_BASE_URL 为空。重新启动前端。
3. 创建管理员账号，在“家庭成员”新增联系人，通过成员邀请建立第二个独立账号。
4. 两个浏览器配置文件/两台设备分别登录。管理员整理计划并批准；指定联系人查看并接手，再记录明确结果。管理员不能冒充另一个联系人接手。
5. 若已有演示数据库，建议为联调实例配置新的 JIAYOUBEI_D1_ID，保留原数据库；不要删除 `.wrangler/` 里的既有记录。

新表由迁移 `0007_care_confirmation.sql` 和服务端幂等建表维护。已有服务端已创建的表不需要重复执行迁移。云端自动到期推进需部署带 cron 的 Worker；本轮只验证本地可执行路径，未进行线上部署。

## 可复现的软件证据

先运行：

```text
npm run build
npm run test:care:unit
npm run test:care:api
npm run test:care:ha
npm run test:care:bridge
npm run care:replay
node --test tests/care-report.test.mjs
```

API 检查使用全新临时 D1、随机测试口令和两个真实认证会话，不访问现有家庭数据。测试会实际销毁并重建服务实例，检查持久化；受控截止时间注入只用于 synthetic 测试。

HA 检查使用本机假 HTTP 服务，验证动作接口、设备拒绝、提前/迟到回执与去重。它不是实物台架。桥接检查还会实际断开应用接收端、重启采集进程，核对待送事件保留原始 ID 后重送。

## 两终端页面录屏

另开 PowerShell，在项目目录启动真实 API 模式的前端：

```powershell
$env:VITE_USE_MOCK='false'
$env:VITE_API_BASE_URL=''
npm run dev -- --port 3012
```

在原终端运行 `npm run care:prove`。脚本将浏览器 API 请求连接到独立的真实认证测试后端，分别使用两个账号，不需要修改现有家庭数据库。原始录屏、截图与检查 JSON 保存到 `public/evidence/`。

录屏是实际页面操作：批准、查看、接手、未联系到继续、明确核实、刷新恢复。业务输入是构造情景，主画面保留来源标识。

## 报告与比赛 HTML

```text
npm run care:report
npm run test:care:e2e
npm run deck:family
npm run test:deck:family
```

导入匿名正式记录：

```text
node scripts/care/build-evidence-report.mjs --input <匿名JSONL文件>
```

记录格式见 `examples/care/collection-template.jsonl`，模板本身不可当作已采集记录。重复回放同一原始记录不会增加样本量；没有自然正例时召回率为“不可估计”。主动协调时间与总经过时间分别统计。

比赛文件仍为根目录 `家有备-创客比赛.html`，图片、两端实际录屏、程序和报告均内嵌。当前 14 页结构和 6 分钟＋2 分钟节奏保留。
