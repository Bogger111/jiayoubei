# 家有备 P0：关怀确认与协作

执行依据：用户粘贴的完整升级指令。当前品牌与浅色克制玻璃界面保留，首发场景为父母暂未回应。

## 原始基线

- Git 基线：`14295270d645b6b18e1aa0c9f9cdc4137afa8aa1`。原比赛 HTML 可由该提交恢复。
- 固定阈值策略源码：`benchmarks/care/b0-care-agent.ts`。原始版本已实际复现：备注“还没有联系到”会将计划置为 resolved 并跳过后续步骤。
- 原项目已有 D1 家庭隔离、真实账号、成员邀请、任务版本与处理记录；不能将前端情景引擎的问题扩大成整个后端都没有实现。
- 原首页的 carePlan 仅在页面内存中；外部设备回执为本地模拟；家庭记忆支持录入检索，尚未参与个体化学习。

## 目前没有获得的证据

用户确认暂时没有接入硬件。当前项目与进程未配置可用 HA URL、Token 或采集密钥，没有发现已连接串口。本机 8123 端口未监听，Docker Desktop 后端未运行；其他主机上的 HA 尚未定位。旧私有 ESPHome 文件写的是 nodemcuv2（ESP8266），不能据此断言实物是 ESP32；没有修改或烧录旧配置。

目前可报告软件执行、真实认证账号协作、本地 D1 持久化、受控服务重建及本机假 HA 接口契约。硬件台架、真人家庭演练、自然家庭试用、外部消息实际送达均待团队采集。接口契约测试统一标 synthetic，不计入 bench。

图像只保留为经授权的辅助语义观察，不宣称已证明增量收益。个人静默基线 B2 暂不训练；通过时间留出数据证明增量后再启用。

## 运行与查看

- `npm run test:care:unit`：策略和状态语义反例。
- `npm run test:care:api`：两个真实认证测试账号、并发、持久化与服务重建。
- `npm run test:care:ha`：本机假 HA 的真实 HTTP 契约。
- `npm run test:care:bridge`：本机 WebSocket 订阅、白名单、断线持久化与进程重启重送。
- `npm run care:replay`：固定构造输入下的基线与改进策略对照。
- `npm run care:prove`：两浏览器账号访问隔离后端并录屏，前端运行于 localhost:3012。
- `npm run care:report`：从上述原始结果和可选匿名采集数据生成报告。
- `npm run deck:family`：更新当前比赛 HTML；先完成对应的证据采集命令。

比赛时从用户价值讲起，技术与证据页展示正常跟进、未联系到继续、刷新恢复与设备未知四件事。实际实物和试用进度按报告读取，不能把目标写成成果。
